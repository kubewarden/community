# Kubewarden Roadmap Strategy

Kubewarden uses GitHub Issues and Milestones to manage the development roadmap of each component.
This dynamic approach keeps the roadmap current. It avoids the problems of a static document like `MILESTONES.md`.

The roadmap is a collaborative effort. We encourage community members to contribute by opening issues or by commenting on existing ones.
The Kubewarden core team monitors these discussions and adds relevant feedback to the roadmap.

## Milestones

Kubewarden is made of four components: the Admission Controller, the Network Enforcer, the Runtime Enforcer and SBOMscanner.
Each component has its own GitHub milestones. A milestone represents one release of that component.
Each milestone holds the set of issues planned for that release.
Milestones are not fixed. Issues can move between milestones as development progresses, as tests complete, and as the community gives feedback.

## Issues

High-level issues are tagged with the `kind/epic` label.
These issues represent significant features, enhancements, or tasks that the Kubewarden community aims to address.
Subtasks, smaller issues, and pull requests reference these primary epic issues to provide context and track progress toward overarching goals.
